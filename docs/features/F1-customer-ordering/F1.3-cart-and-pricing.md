# F1.3 — Cart & Pricing

Server-authoritative pricing for a draft cart: modifier resolution, tier waivers, totals.

**Traces to**: FR-2.8–2.14 · ADR-0007 (money) · PRD §8.2.

---

## 1. The rule everything else follows

**The request contract carries no price field.** Not "prices are validated" — there is nowhere to put one.

```json
{ "items": [ { "clientLineId": "UUID", "menuItemId": "i1…", "qty": 1,
               "modifierOptionIds": ["m_large", "m_oat"] } ] }
```

A client cannot propose a price, so there is no tampering path to defend against — the attack surface is removed rather than guarded (threat T2). `/quote` and `/orders` call the **same** `domain.priceCart()`, so the quoted total and the placed total cannot diverge.

The optional `expectedTotalMinor` on placement is **advisory only**: it lets the server detect that the customer was looking at a stale price and return `409 PRICE_CHANGED` with the new quote, rather than silently charging something different (F1.6 §2).

## 2. API

### `POST /public/orders/quote`

Pure computation. **No writes, no side effects** — safe to call on every cart mutation.

**Request** (session token in `Authorization`)

```json
{
  "items": [
    { "clientLineId": "UUID-1", "menuItemId": "i1…", "qty": 2, "modifierOptionIds": ["m_large", "m_oat"] },
    { "clientLineId": "UUID-2", "menuItemId": "i5…", "qty": 1, "modifierOptionIds": [] }
  ]
}
```

**Response 200**

```json
{
  "lines": [
    {
      "clientLineId": "UUID-1",
      "menuItemId": "i1…",
      "qty": 2,
      "unitPriceMinor": 9000,
      "modifierTotalMinor": 2500,
      "lineTotalMinor": 23000,
      "modifiers": [
        { "id": "m_large", "priceDeltaMinor": 2500, "waivedByTier": false },
        { "id": "m_oat",   "priceDeltaMinor": 1500, "waivedByTier": true }
      ]
    },
    {
      "clientLineId": "UUID-2", "menuItemId": "i5…", "qty": 1,
      "unitPriceMinor": 4500, "modifierTotalMinor": 0, "lineTotalMinor": 4500,
      "modifiers": []
    }
  ],
  "subtotalMinor": 27500,
  "discountMinor": 0,
  "totalMinor": 27500,
  "eta": { "lowerMinutes": 8, "upperMinutes": 12, "queueDepth": 3 },
  "loyalty": { "pointsToEarn": 33, "tier": "silver", "multiplier": 1.2 },
  "unavailable": [],
  "payAt": "counter",
  "traceId": "0af7651916cd43dd"
}
```

Note `m_oat` shows `priceDeltaMinor: 1500` **and** `waivedByTier: true`, rather than a delta of zero. The customer sees "1500 struck through" — the perk is visible, which is the point of having it (F1.5 §2). The waiver is applied by the server; the client's rendering of it is cosmetic.

**Response 200 with unavailable items** — still 200, because the cart is a draft:

```json
{
  "lines": [ /* only the available lines */ ],
  "subtotalMinor": 4500, "totalMinor": 4500,
  "unavailable": [
    { "clientLineId": "UUID-1", "menuItemId": "i1…", "reason": "item_unavailable" },
    { "clientLineId": "UUID-2", "menuItemId": "i5…", "modifierOptionId": "m_oat", "reason": "modifier_unavailable" }
  ]
}
```

The webview corrects the cart rather than failing at checkout (FR-2.7). Every quoted or unavailable row echoes the client-generated `clientLineId`, so it can be reconciled even when a cart contains the same menu item with different modifiers. Failing here would be the wrong shape — the customer has done nothing wrong.

**Errors**: `422 MODIFIER_GROUP_REQUIRED` (with `groupId`), `422 MODIFIER_SELECTION_INVALID` (with `groupId`, `min`, `max`, `got`), `409 MENU_VERSION_GONE`, `401 SESSION_EXPIRED`.

## 3. Pricing algorithm

Lives in `packages/domain/pricing.ts`. **Pure**: no I/O, no clock, no database. Takes the resolved menu version and the customer's tier as inputs.

```
priceCart(cart, menu, tier):
  for each line:
    unitPrice   = menu.item(id).basePriceMinor            ← from the pinned version
    modifiers   = resolve each optionId against its group
    validate    → required groups selected; min/max respected
    for each modifier:
      delta = option.priceDeltaMinor
      waived = option.freeForTier != null
               && tierRank(tier) >= tierRank(option.freeForTier)
      effectiveDelta = waived ? 0 : delta
    modifierTotal = Σ effectiveDelta
    lineTotal     = (unitPrice + modifierTotal) × qty      ← multiply LAST
  subtotal = Σ lineTotal
  total    = subtotal − discount
```

Three things that look like details and are not:

**Multiply by quantity last.** `(unit + modifiers) × qty`, never `unit × qty + modifiers`. The second form silently charges one set of modifiers for two drinks — a bug that is invisible on quantity 1 and wrong on every larger order.

**Tier waivers are ranked, not equality-matched.** `freeForTier: "silver"` means Silver *and above*. Comparing for equality would give Gold customers fewer perks than Silver, which is the kind of thing nobody notices until a Gold customer does.

**No floats anywhere.** All arithmetic is on `Minor` integers (ADR-0007). The branded type makes a plain number un-addable to a money value, enforced by lint.

## 4. Data access and caching

**The quote path touches the database zero times on the happy path.**

| Input | Source |
|---|---|
| Menu (items, prices, modifiers) | Redis `menu:{tenantId}:{version}` — populated at publish |
| Availability | Redis `avail:{tenantId}` — event-invalidated |
| Customer tier | The **session token** (`F1.1 §2`) — already verified |
| Queue depth for ETA | Redis `queue:{tenantId}` — maintained by the event bus (F1.4 §4) |

Everything is either in the signed token or in Redis. That is why quote can be called on every keystroke of a quantity stepper without concern.

**Tier in the token is deliberate.** It is 15 minutes stale at worst. A customer who crosses into Silver mid-session gets the perk on their *next* session — which is correct behaviour anyway, since the crossing happens on collection (F1.5), not mid-cart.

## 5. Edge cases

| Case | Behaviour |
|---|---|
| Same item, different modifiers | Separate lines. Never merged — they are different drinks |
| Same item, identical modifiers | Client merges into one line with `qty: 2`. Server accepts either shape |
| `qty` ≤ 0 or > 20 | `422`. Upper bound is a sanity guard, tenant-configurable |
| Empty cart | `200` with zero totals. Not an error — it is the initial state |
| Unknown `menuItemId` | `409 MENU_VERSION_GONE` — it means the client is on a different version |
| Modifier id not in the item's groups | `422 MODIFIER_SELECTION_INVALID`. Never silently ignored |
| Duplicate option id in one line | Deduplicated, charged once |
| Optional group with no selection | Valid. Only `required` groups block |
| Below `minOrderValueMinor` | Quote succeeds; **placement** returns `422 MIN_ORDER_VALUE`. Browsing is never blocked |

## 5a. Upsell & cross-sell (FR-2.12, FR-2.13) — status

Both are **built on the frontend against mocks**; the two endpoints below are contracted
(`upsellResponse`, `pairingsResponse` in `packages/contracts`) but **not yet implemented**.
The webview `datasource` calls the real path and falls back to a mock on `404`
(`features/cart/mockUpsell.ts`, `features/cross-sell/mockPairings.ts`) — delete the fallbacks
when the routes land.

| | Endpoint (TBD) | Frontend behaviour |
|---|---|---|
| **Upsell** (2.3) | `GET /public/upsell` → `{ item: MenuItem \| null }` — one café-flagged add-on | An inline card in the cart, shown **once per session** after the first item, never for an item already in the cart |
| **Cross-sell** (2.5) | `GET /public/pairings?items=<id,id>` → `{ pairings: MenuItem[] }` — order co-occurrence for the cart | A full screen between "Review order" and confirm; **suppressed** when the list is empty; shown at most once per session; Skip / Continue both go to checkout |

**Backend still to decide.** The upsell source is a per-item flag (`menu_items.is_upsell`) or
the settings registry. The cross-sell source is order co-occurrence — FR-2.13 names
`mv_item_sales_daily`, but that view holds *per-item* daily aggregates, not pair counts; a
self-join over `order_items` (which has a `(tenant_id, menu_item_id, order_id)` index) is the
likely v1, with a materialized pair table only if volume needs it. Drop pairs seen fewer than
a small threshold rather than showing a weak suggestion.

## 6. Tests

This is the highest-value unit-test surface in F1 — it decides money.

**Unit** (`packages/domain`, 100% branch): modifier deltas; tier waivers at every rank boundary including Gold-inherits-Silver; required-group violations; min/max selection; **quantity multiplication with modifiers**; rounding at each boundary; empty cart; duplicate options.

**Property** (`fast-check`):
- **PROP-2** — cart total is independent of the order items were added in.
- **PROP-6** — `Σ lineTotalMinor == totalMinor` for any cart at any discount. No piastre created or destroyed.

**Integration** — `/quote` and `/orders` produce identical totals for the same cart (this is what guarantees the two cannot drift); an 86'd modifier appears in `unavailable[]` rather than throwing.
